# 中文使用与提交说明

版本：1.0.1。主执行指令保留英文；本文件方便参赛者阅读、调用和核对。赛事题面没有要求说明必须用英文。最终 PPT 和讲稿的语言以实际案例要求为准，可以是中文、英文或指定的双语。

## 一、这个包是什么

这是“论文转学术 PPT”的 Skill 资源包，包含执行指令、三个辅助脚本、接口与方法说明。它需要由能够读写文件、执行命令的 Agent 加载。它不是一个双击即可启动的独立软件，也不是预先做好的三套正式案例答案。

能力包括：读取真实论文与模板，组织汇报主线，为每页主张标记来源，按模板创建或修改可编辑 PPT，添加讲稿备注，并尝试真实导出 PDF/PNG 预览。主张是否符合论文含义、版面是否清晰，仍需 Agent 阅读原文和查看真实预览。

## 二、目录与文件

| 文件 | 用途 |
|---|---|
| `SKILL.md` | Agent 加载的主执行指令 |
| `scripts/prepare.py` | 输入与环境检查、论文/模板读取、页面截图或裁剪、版本与哈希记录 |
| `scripts/deck.py` | 按蓝图生成或定点修改 PPT，保留原生文本、表格和图表 |
| `scripts/audit.py` | 证据、PPT、输出字段检查及真实渲染 |
| `references/interfaces.md` | 证据表与页面蓝图的准确字段和调用接口 |
| `references/method.md` | 科学准确性、模板适配和异常处理规则 |
| `references/usage.md` | 依赖、调用示例和适用范围 |
| `agents/openai.yaml` | 支持此配置的客户端使用的中文显示名称和默认提示 |
| `GITHUB_URL.txt` | 真实公开作品链接；当前为空，尚未获得对应附加分 |

不要翻译文件名、命令、代码变量或 JSON/YAML 字段。中文解释、幻灯片标题和讲稿正文可以使用 UTF-8 中文。

## 三、最小调用方式

将目录交给支持 Skill 的 Agent，并使用以下提示：

> 请加载 evidence-paper-slides。读取本次实际任务、论文和模板，按原始 output_contract 完成论文转学术 PPT。输出可编辑演示文件、逐页证据映射、讲稿备注和真实 PDF/PNG 预览；遵守任务要求的语言、页数与时长，如实记录不确定性和失败事项。

竞赛评测器会将 Skill 安装到 `/skills/weekly-skill`。该路径是平台运行约定，不是要求你在自己的 Windows 电脑上创建同名目录。运行时先读实际 `/input/case.json`、`task.md` 和 `environment/resources.yaml`，再处理对应论文和模板。辅助脚本的完整命令见 `usage.md`、`interfaces.md`，不需要用户先手工把论文拆成答案。

关键证据字段统一为 `pdf_page`（从 1 开始的 PDF 物理页码）、`excerpt`（原文短摘录）、`claims`（逐条主张）和 `source_ids`（来源标识）。不要再使用旧的 `page`、`quote` 写法。每个实质性页面必须有逐条证据映射。

## 四、中文字体与预览

中文 PPT 必须检查运行环境实际可用的中文字体，并查看导出预览中的汉字、标点、数学符号和单位。系统有某种英文字体，并不代表能正常显示中文。优先遵循指定模板；如果需要替代字体，记录原字体、替代字体、原因，并重新渲染检查。

已有测试验证了虚构英文材料的生成、定点修改、证据检查与真实 LibreOffice 渲染。它不能证明所有中文字体都可用，也不代表已在 Microsoft PowerPoint 中测试播放。无法完成渲染或字体核对时，要如实报告限制，不能伪称“换机无问题”。

## 五、官方案例与资源清单

组织方三个固定案例的材料应由平台实际评测运行提供。当前公开资源页只展示 interface-example、工具和说明资源名称，没有提供这些卡片的逐项下载链接。不能把“资源（12）”当作十二个公开测试案例，也不能据此假定某个具体工具命令已存在。

本包没有包含三个官方案例、预制正式答案、白板或虚构得分。先前软件检查所用数据明确标注为虚构，只用于检查文件处理流程。

## 六、正式提交前的事项

1. 保留完整目录结构，提交目录根部必须有 `SKILL.md`。题面约定的提交位置为 `/app/submission/`。
2. 本压缩包是 Skill 源文件包，不是已经完成提交的官方 ARM 包。如何交付源码、打包、附带真实 Agent 日志及触发评分，需要按平台实际提交入口和官方文档执行，不能假定把 ZIP 下载到电脑就已参赛。
3. 官方参赛文档提供 `playground task download`、`playground submit` 等命令，并要求真实会话日志。提交路线还取决于该题实际评分策略；应先核对实际题目和入口，不在本说明中预设尚未验证的上传路径。文档入口：https://play.bohrium.com/api/docs/compete-and-submit 。
4. 如果争取 GitHub 附加分，须先真实公开作品，将有效链接填到 `GITHUB_URL.txt` 第一行，再核实未登录也能访问。本包不会替你创建或公开仓库。
5. 运行正式评测后，根据真实错误和结果调整。当前没有官方三个案例的测试成绩，不承诺得分或排名。
